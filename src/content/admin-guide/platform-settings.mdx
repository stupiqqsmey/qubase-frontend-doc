# Platform Settings

Platform Settings allow administrators to configure system-wide options that affect the behavior of the Qubase platform.

These settings help administrators maintain a consistent environment, manage platform behavior, and support users across all workspaces and projects.

---

## Before you begin

Before modifying Platform Settings, ensure that you have:

- Administrator access
- Permission to manage platform settings

> [!NOTE]
> Changes to Platform Settings may affect multiple users and workspaces across the platform.

---

## What are Platform Settings?

Platform Settings provide centralized configuration for Qubase.

Depending on your platform configuration, administrators may be able to manage:

- General platform settings
- System preferences
- Platform configuration
- Administrative options

The available settings depend on your platform configuration.

---

## Access Platform Settings

To open Platform Settings:

1. Sign in as an administrator.
2. Open the **Admin Dashboard**.
3. Navigate to **Platform Settings**.

The settings page displays the available platform configuration options.

---

## Configure platform settings

To update a platform setting:

1. Open **Platform Settings**.
2. Select the category you want to configure.
3. Update the available settings.
4. Review your changes.
5. Save the configuration.

Changes become effective according to your platform configuration.

---

## Configuration overview

Platform Settings may include:

| Category | Description |
| -------- | ----------- |
| General | Platform-wide configuration |
| Preferences | Default platform behavior |
| Administration | Administrative configuration |
| System | Platform maintenance options |

Available categories depend on your deployment.

---

## Benefits

Platform Settings help administrators:

- Maintain consistent platform behavior
- Improve system organization
- Configure platform defaults
- Support platform maintenance

---

## Best practices

- Review configuration changes before saving.
- Make one change at a time when possible.
- Document important administrative changes.
- Verify platform behavior after configuration updates.

> [!TIP]
> Test important configuration changes in a non-production environment whenever possible.
